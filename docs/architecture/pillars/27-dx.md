# 27. Developer Experience (DX)

### 27.1 Quy tắc "một lệnh để dev"

```bash
./vendor/bin/sail up    # hoặc: composer dev
```

Phải: boot Postgres + Redis + Mailpit · chạy migration · seed data · start app + queue worker + Vite hot reload · in URL app/docs/mail/DB UI. Nếu engineer mới không thể `git clone && sail up` và chạm app trong 10 phút → sửa gap đó.

### 27.2 Seed data

Thực tế, idempotent: 5 workspace khác plan · 20 user mỗi role có ít nhất một · 100 resource đại diện · 1 demo workspace ai cũng browse được. Dùng **Factories** + **Seeders**.

### 27.3 Tooling dev trong Sail

**Mailpit** (đọc email giao dịch ở dev) · **pgweb/Adminer** (xem DB) — thêm vào `docker-compose.yml`.

### 27.4 Conventions

`composer.json` scripts là entry point (`dev`, `test`, `migrate`). `.env.example` checked-in, `.env` gitignored. `CONTRIBUTING.md` với 5 lệnh dev mới cần. `docs/decisions/` cho ADR.

### 27.5 Codegen, không boilerplate

API client gen từ OpenAPI (Scribe export) · route type-safe (Inertia + Wayfinder/Ziggy) · translation key type-check. Viết cùng thứ ở 3 chỗ → generate nó.
